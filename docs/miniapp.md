# مینی‌اپ پیام‌رسان‌ها (نسخهٔ `/mini`)

ماژولی سبک و تمام‌صفحه برای داخل وب‌ویو پیام‌رسان‌ها (بله، تلگرام، ایتا، وایتا) و
همین‌طور مرورگر عادی. دو کار را با هم انجام می‌دهد:

- **مشتری**: دیدن سالن‌های خودش (توضیحات، تازه‌ترین پکیج‌ها، آرایشگران، ساعات کاری، نظرات،
  راه‌های تماس)، انتخاب روز و ساعت و ثبت نوبت، «نوبت بعدی من» با شمارش معکوس،
  تغییر وقت / لغو / ثبت نظر، نزدیک‌ترین وقت خالی، لیست انتظار، «علاقه‌مندی‌ها»،
  اطلاعیه‌ها، کیف پول و تیکت پشتیبانی.
- **صاحب سالن**: هاب چهارتبهٔ «امروز / پکیج‌ها / مشتریان / مالی» — آمار روز، نوبت‌های هر روز،
  تأیید انبوه، «انجام شد»، «حاضر نشد»، ثبت نوبت حضوری، ویرایش سریع پکیج‌ها، کارت مشتری،
  صندوق امروز و نمودار درآمد.

**فلسفهٔ طراحی: یک کار در هر صفحه.** دکمه‌ها درشت‌اند، هر کاری با یک لمس باز می‌شود
(شیت پایین‌کشویی، نه فرم وسط صفحه)، هیچ جا لازم نیست کاربر چیزی «پیدا» کند:
نوبت بعدی، نزدیک‌ترین وقت خالی و اطلاعیه‌های خوانده‌نشده خودشان بالای صفحه‌اند.

**مینی‌اپ سالن‌محور است، نه فهرست سالن‌ها.** در `/mini` هیچ جست‌وجو یا لیستی از
سالن‌های دیگر وجود ندارد و **هیچ «سالن نمونه‌ای» به کاربر نشان داده نمی‌شود** (کلید
سوپرادمین `miniapps.default_salon` حذف شده است). کاربر فقط سالن‌هایی را می‌بیند که
خودش آورده: یا سالن خودش است، یا از آن نوبت گرفته، یا با **اسکن کیو‌آر / باز کردن لینک**
به «علاقه‌مندی‌هایش» اضافه کرده است. زنجیرهٔ تشخیص «سالن صفحهٔ خانه» در `lib/resolve.ts`:

1. اسلاگ داخل لینک/کیو‌آر — `/mini?salon=mah` (یا `slug`، `s`، `startapp`، `startparam`)
   **یا نشانی خودِ سالن** — `mah.nobino.ir/mini` (در dev: `mah.localhost:5175/mini`)؛ §۳.۵
2. سالن خود کاربر، اگر `SALON_OWNER` باشد — `GET /api/dashboard/stats` → `stats.slug`
3. آخرین سالنی که کاربر از آن نوبت گرفته — `GET /api/appointments?limit=1` → `appointments[0].salonSlug`
4. اگر دقیقاً یک سالن در علاقه‌مندی‌هایش باشد — `GET /api/favorites` → همان خانه می‌شود

اگر هیچ‌کدام نبود، خانه **فهرست علاقه‌مندی‌ها** را نشان می‌دهد (با دو سالن به بالا) و اگر
فهرست خالی باشد فقط راهنمای اسکن کیو‌آر و دکمهٔ ورود — **هیچ سالن دیگری فاش نمی‌شود**.

**اسکن کیو‌آر = ثبت در علاقه‌مندی‌ها.** کارت کیو‌آر سالن در سایت (`components/SalonQrCard.tsx`)
دو هدف دارد: «صفحهٔ وب» و «مینی‌اپ». قطب مینی‌اپ نشانی خودِ سالن را با `/mini` می‌سازد —
`http://mah.localhost:5175/mini` در توسعه و `https://mah.nobino.ir/mini` در پروداکشن
(`salonMiniUrl`؛ اگر همان‌جا روی ساب‌دامین سالن باشیم هم همین آدرس، پس `mah.mah` ساخته
نمی‌شود). فقط روی میزبان IP یا دامنهٔ اختصاصی که اسلگ از میزبان بیرون کشیده نمی‌شود، به
`<miniUrl>?salon=<slug>` پنل برمی‌گردد. هر کاربری که لینک مینی‌اپ یک سالن را باز کند، آن
سالن به علاقه‌مندی‌هایش اضافه می‌شود؛ اگر وارد نشده باشد اسلاگ در `localStorage` می‌ماند و
بعد از ورود خودش اضافه می‌شود. سقف منطقی فهرست ۲۰ سالن است.


همه‌چیز از پنل سوپرادمین تنظیم می‌شود؛ هیچ فایلی خارج از پوشهٔ ماژول تغییر نکرده
مگر چند نقطهٔ اتصال (_mount_ در `App.tsx`، بخش تنظیمات، و اصلاح کوچک API مشترک).

## ۱) آدرس و مسیرها

| مسیر | محتوا |
|------|-------|
| `/mini` | خانهٔ سالن‌محور: بنر اطلاعیهٔ سوپرادمین، سربرگ سالن، دربارهٔ سالن و راه‌های تماس، «نوبت بعدی من» با شمارش معکوس و کارهایش، تازه‌ترین پکیج‌ها، تیم، ساعات کاری، نظرها، دکمهٔ رزرو و نوار افقی «علاقه‌مندی‌های شما». اگر سالنی برای نمایش نباشد: فهرست علاقه‌مندی‌ها یا راهنمای اسکن کیو‌آر. روی نشانی خودِ سالن (`mah…/mini`) خانه همان سالن است و به علاقه‌مندی‌ها هم اضافه می‌شود — §۳.۵ |
| `/mini/s/<slug>` | رزرو همان سالن: خدمت (از خانه پیش‌انتخاب می‌شود: `?service=<id>`) → آرایشگر → روز → ساعت → ثبت نوبت. اگر روزی پر باشد دو دکمهٔ «نزدیک‌ترین وقت خالی» و «لیست انتظار» ظاهر می‌شود. دکمهٔ ♥ در سربرگ، سالن را به علاقه‌مندی‌ها اضافه/از آن حذف می‌کند (بدون ورود، شیت ورود را باز می‌کند) |
| `/mini/favorites` | «علاقه‌مندی‌های من»: فهرست چند سالنه با «رزرو» و حذف، افزودن سالن با **دکمهٔ اسکن کیو‌آرِ دوربین** (§۳.۴) یا با چسباندن لینک/اسلگ، و راهنمای اسکن برای وقتی که فهرست خالی است |
| `/mini/appointments` | نوبت‌های من (پیشرو / تاریخچه) + تغییر وقت، لغو و ثبت نظر روی نوبت‌های خود کاربر |
| `/mini/voice-booking` | «رزرو با هوش مصنوعی و دستی» (سربرگ پنجم نوار پایین با برچسب «رزرو هوشمند»): دو حالت در یک صفحه — **با صدا**: ضبط ویس (یا آپلود فایل صوتی، یا نوشتن جمله) → تبدیل گفتار به متن → استخراج نام/شماره/خدمت/روز/ساعت → تطبیق با وقت‌های واقعی سالن و ثبت نوبت؛ **دستی**: خدمت ← آرایشگر ← روز ← ساعت ← نام و شماره. جزئیات در §۳.۳ |
| `/mini/notifications` | اطلاعیه‌ها (تأیید/تغییر/لغو نوبت، یادآور، اشتراک) + «خواندن همه»؛ شمارندهٔ خوانده‌نشده روی زنگولهٔ نوار بالا است |
| `/mini/support` | ثبت تیکت پشتیبانی و فهرست تیکت‌های خود کاربر با پاسخ اپراتور |
| `/mini/manage` | هاب مدیریت سالن (فقط نقش‌های `SALON_OWNER`، `AGENT`، `ADMIN`)؛ تب با `?tab=` مستقیم باز می‌شود: `today` (پیش‌فرض) · `services` · `customers` · `finance` |
| `/mini/me` | حساب: اطلاعات تماس، تعداد نوبت، کیف پول و ۴ تراکنش آخر، اتصال حساب پیام‌رسان، دسترسی سریع و خروج |

آدرس کامل را خودِ بک‌اند از `miniapps.base_url` (یا `SITE_URL`) می‌سازد و در
`GET /api/mini/config` با فیلد `miniUrl` برمی‌گرداند.

ساختار پوشه‌ها:

```
frontend/src/mini/
  MiniApp.tsx        پوسته: نوار بالا (زنگولهٔ اطلاعیه‌ها)/پایین، مسیرها، دکمهٔ «برگشت» پیام‌رسان
  mini.css           استایل ماژول (کاملاً scoped زیر `.mini-root`)
  lib/bridge.ts      تشخیص پلتفرم، initData، هپتیک، بستن وب‌ویو
  lib/store.tsx      کانفیگ + نشست + سبد رزرو + توست (MiniProvider)
  lib/resolve.ts     زنجیرهٔ «سالن صفحهٔ خانه» (لینک/نشانی سالن ← سالن خودم ← آخرین نوبت ← علاقه‌مندی)
  lib/host.ts        اسلگ سالن از میزبان (`mah.nobino.ir/mini`) — مستقل از کد سایت (§۳.۵)
  lib/favorites.ts   کش مشترک علاقه‌مندی‌ها + `useFavorites` (به‌ازای هر کاربر یک کش،
                     افزودن/حذف خوش‌بینانه با بازگشت به حالت اول اگر سرور رد کرد،
                     و `localStorage` برای اسکن‌های پیش از ورود)
  lib/format.ts      تاریخ شمسی، تومان، عدد فشرده («۲/۹ میلیون»)، رقم فارسی، نرمال‌سازی شماره
  lib/types.ts       تایپ‌های پاسخ API
  components/
    ui.tsx           دکمه، شیت، کارت، آیکون‌ها، نوار وضعیت
    booking.tsx      نوار روزها، شبکهٔ ساعت‌ها، شیت تکمیل نوبت، شیت لیست انتظار
    appt-actions.tsx ردیف کارهای یک نوبت + شیت‌های تغییر وقت / لغو / ثبت نظر
    favorites.tsx    چیپ نوار افقی و ردیف کامل یک سالن در علاقه‌مندی‌ها
    manage.tsx       تب‌های پکیج‌ها، مشتریان و مالیِ هاب مدیریت
    login-sheet.tsx  ورود OTP
    qr-scanner.tsx   شیت تمام‌صفحهٔ دوربین + خواندن کیو‌آر با jsQR/BarcodeDetector (§۳.۴)
  pages/             MiniHome، MiniSalon، MiniBookings، MiniVoiceBooking،
                     MiniNotifications، MiniSupport، MiniManage، MiniMe، MiniFavorites
```

ماژول هیچ کامپوننتی از بقیهٔ سایت import نمی‌کند، `AuthProvider` سایت را مصرف نمی‌کند
و استایلش با `tailwind` صفحات اصلی قاطی نمی‌شود؛ به همین دلیل می‌توان آن را بدون
ریسک حذف کرد یا به دامنهٔ دیگری منتقل کرد.

## ۲) تنظیمات از پنل سوپرادمین

بخش **«مینی‌اپ پیام‌رسان‌ها»** در `پنل ادمین ← تنظیمات سیستم` (کلیدهای `miniapps.*` در
جدول `Setting`؛ مقادیر `secret` رمزنگاری‌شده ذخیره می‌شوند):

| کارت | کلیدها | اثر |
|------|--------|-----|
| تنظیمات پایه | `base_url`، `manage_tab`، `featured` | آدرس پایه، نمایش تب مدیریت، اسلاگ‌های ویژه (فقط برای `GET /api/mini/featured`؛ مینی‌اپ دیگر فهرست نمی‌سازد) |
| ظاهر و برندینگ | `title`، `subtitle`، `accent`، `hero_text`، `support_phone`، `show_prices` | نام/زیرعنوان، رنگ اصلی (hex)، متن قهرمان، تلفن پشتیبانی، نمایش قیمت‌ها |
| ویژگی‌ها و امنیت ورود | `allow_booking`، `allow_reviews`، `require_login`، `silent_login` | روشن/خاموش بودن رزرو، نظرات، ورود اجباری، ورود بی‌حس |
| تلگرام / بله / ایتا / وایتا | `<p>.enabled`، `bot`، `app`، `link`، `token` | فعال‌سازی، نام ربات و نام اپ، لینک رسمی نصب، توکن ربات (فقط سمت سرور) |

`token` هرگز به کلاینت نمی‌رود؛ `GET /api/mini/config` فقط `enabled`، `installUrl` و
`silentLogin` را می‌فرستد.

هیچ کلیدی در پنل «چه کسی چه سالنی ببیند» تعیین نمی‌کند. کلید قدیمی
`miniapps.default_salon` از `settings-catalog`، از `lib/mini/config.ts` و از پاسخ
`GET /api/mini/config` حذف شده است؛ اگر ردیفی از آن در جدول `Setting` باقی مانده باشد
دیگر خوانده نمی‌شود و بی‌اثر است. منبع خانه فقط لینک/کیو‌آر، سالن خود کاربر و
علاقه‌مندی‌های اوست.

برای فعال کردن یک پیام‌رسان:

1. در پنل، `enabled` را روی «روشن» بگذارید و `bot` + `app` را پر کنید (یا `link` را مستقیم بدهید).
2. توکن ربات را از BotFather / پنل رباتِ همان پیام‌رسان در فیلد `token` ذخیره کنید.
3. آدرس `https://your-domain/mini` را به‌عنوان Mini App به ربات وصل کنید.
4. کاربر از طریق لینک `installUrl` وارد می‌شود؛ برای ایتا و وایتا چون استاندارد
   `initData` امضاشدهٔ تلگرام را ندارند، `link` را دستی از پنل پیام‌رسان وارد کنید.

**بنر بالای خانه** از تنظیمات مینی‌اپ جداست: همان «اطلاعیهٔ سراسری» که سوپرادمین در
پنل می‌نویسد و از `GET /api/public/announcement` می‌آید. اگر خالی باشد بنر رندر نمی‌شود،
و کاربر می‌تواند با ✕ آن را برای همان متن ببندد (در `localStorage` می‌ماند).

سقف‌های «پروندهٔ مشتری» (تعداد یادداشت/عکس/ویس و حجم فایل‌ها) در این بخش نیست؛
در بخش مستقل **«پروندهٔ مشتریان (CRM)»** با کلیدهای `crm.*` قرار دارد و روی مینی‌اپ و
پنل وب هر دو اعمال می‌شود — جزئیات در ۳.۲.

## ۳) مسیرهای API ماژول

| مسیر | متد | توضیح |
|------|-----|-------|
| `/api/mini/config` | GET | برندینگ، ویژگی‌ها، `miniUrl` (پایهٔ ساخت کیو‌آر مینی‌اپ)، پلتفرم‌ها و لینک نصب |
| `/api/mini/session` | POST | ورود بی‌حس با `initData` (پاسخ: `linked` / `needsPhone` / `mode: otp` / خطای ۴۰۱) |
| `/api/mini/link` | POST | اتصال حساب پیام‌رسان به حساب نوبینو (نیازمند نشست) |
| `/api/mini/staff?slug=` | GET | آرایشگران فعال یک سالن، با خدمات مجازشان |
| `/api/mini/featured` | GET | سالن‌های انتخاب‌شده توسط سوپرادمین — برای صفحهٔ عمومی سایت؛ مینی‌اپ از آن استفاده نمی‌کند |

بقرهٔ کار (رزرو، ساعت خالی، نظرات، لغو، تغییر وقت، آمار، صندوق، تیکت، کیف پول) همان
endpoint های قبلی سایت است؛ مینی‌اپ مسیر تازه‌ای اضافه نکرده، پس `gen-controllers.mjs`
هم لازم نیست:

| گروه | مسیرها |
|------|--------|
| ورود و حساب | `/api/auth/otp/*`، `/api/auth/me`، `/api/auth/logout` |
| سالن و رزرو | `/api/salons/:slug`، `/api/salons/:slug/availability`، `/api/salons/:slug/reviews`، `POST /api/salons/:slug/waitlist`، `POST /api/appointments`، `GET /api/appointments`، `POST /api/appointments/:id/cancel`، `POST /api/appointments/:id/reschedule`، `PATCH /api/appointments/:id` |
| اطلاعیه و پشتیبانی | `GET /api/notifications?limit=&page=` (فقط `channel=IN_APP`)، `PATCH /api/notifications` = «خواندن همه»، `GET|POST /api/support` |
| کیف پول | `GET /api/wallet?limit=4` (تراکنش‌های `createdAt` شمسی از قبل فرمت‌شده) |
| علاقه‌مندی‌ها | `GET /api/favorites?limit=20` (پاسخ: `favorites[{id, salon{id, slug, name, city, coverColor, bannerUrl}}]`)، `POST /api/favorites/:salonId` (upsert؛ دو بار فشار دادن هم ۲۰۱ می‌دهد و تکراری نمی‌سازد)، `DELETE /api/favorites/:salonId`. هر سه نشست می‌خواهند و `:salonId` شناسهٔ `cuid` سالن است نه اسلاگ — برای همین قبل از افزودن از لینک، `GET /api/salons/:slug` صدا زده می‌شود. جدول `Favorite` و این endpoint ها از قبل در سایت بودند (پنل وب هم مصرفشان می‌کند)؛ مینی‌اپ چیزی به بک‌اند اضافه نکرده است |
| آمار و مدیریت سالن | `/api/dashboard/stats`، `/api/dashboard/salons/:id/services` (+ `/:serviceId` برای PATCH/DELETE)، `/customers`، `/cash`، `/financial?from=&to=`، `/revenue`، `/reminders?date=` |
| عمومی | `GET /api/public/announcement` (بنر بالای خانه) |

بنابراین قوانین سالن، قفل همزمانی نوبت، پیامک‌ها و کمیسیون در مینی‌اپ هم دقیقاً همان است.
تغییر وضعیت نوبت (`PATCH /api/appointments/:id`) برای `SALON_OWNER`/`ADMIN`/`AGENT` باز است؛
دکمه‌های مشتری («تغییر وقت»، «لغو»، «ثبت نظر») فقط روی نوبتی می‌آید که
`customerPhone` همان شمارهٔ کاربر است — در فهرستِ نوبت‌های سالن، مسئول سالن
به تب «مدیریت» راهنمایی می‌شود.

`GET /api/salons/:slug` برای خانهٔ مینی‌اپ غنی‌تر شد: علاوه بر `services`/`hours`/`gallery`
حال `timezone`، `whatsapp`، `instagram`، `website`، `mapUrl`، `neshanUrl`، `baladUrl` و در
هر خدمت `category` و `createdAt` را هم برمی‌گرداند («تازه‌ترین پکیج‌ها» بر پایهٔ
`createdAt` مرتب می‌شود). `/api/salons/search` دیگر توسط مینی‌اپ صدا زده نمی‌شود.
برای بیعانه، همان پاسخ `depositEnabled`، `depositMode` (`FIXED`/`PERCENT`) و
`depositValue` را هم دارد (تومان برای FIXED، درصد برای PERCENT).

### ۳.۱) بیعانهٔ نوبت (پیش‌پرداخت رزرو)

سالن‌دار از پنل (تنظیمات سالن ← «بیعانهٔ نوبت») بیعانه را فعال می‌کند و مبلغ ثابت
یا درصدی از قیمت خدمت تعیین می‌کند (`PATCH /api/dashboard/salons/:id` با
`depositEnabled`/`depositMode`/`depositValue`). چرخهٔ پرداخت:

1. **ثبت نوبت:** `POST /api/appointments` برای مشتری (مهمان یا `CUSTOMER`) طبق تنظیم
   سالن `depositAmount` را روی نوبت می‌نویسد (سقف آن قیمت خدمت است). نوبتی که
   سالن‌دار از پنل خودش ثبت کند بیعانه نمی‌گیرد — بیعانه در محل دریافت می‌شود.
2. **شروع پرداخت:** `POST /api/payments/create` با بدنهٔ `{appointmentId}` (بدون پکیج؛
   نیازمند ورود و فقط صاحب نوبت با `customerId` یا همان `customerPhone`).
   پاسخ `redirectUrl` درگاه است. پرداخت دوباره رد می‌شود («بیعانه قبلاً پرداخت شده است»).
3. **درگاه و بازگشت:** در سندباکس کاربر به `/api/payments/mock-pay?...&appointment=<id>`
   می‌رود و درگاه به `/api/payments/callback/<gateway>?appointment=<id>&...` برمی‌گردد؛
   `handlePaymentCallback` شاخهٔ `appointmentId` دارد و بعد از verify موفق،
   `depositPaid=true` روی نوبت و `status=PAID` روی `Payment.appointmentId` می‌نشیند
   (idempotent — بازگشت تکراری دوباره اعمال نمی‌شود). کاربر به `/mini?status=success` برمی‌گردد.
4. **نمایش:** کارت «نوبت بعدی» خانه و فهرست نوبت‌ها اگر `depositAmount && !depositPaid`
   باشد دکمهٔ «پرداخت بیعانه» نشان می‌دهند.

پیاده‌سازی: `backend/src/lib/bookings/create.ts` (`depositForSalon`)،
`backend/src/lib/payments/engine.ts` (`createDepositPayment`، `handleDepositCallback`)،
`backend/src/routes/api/payments__create.ts`، `payments__callback__gateway.ts`،
`payments__mock-pay.ts`، و سمت مینی‌اپ `frontend/src/mini/lib/deposit.ts`
(`startDepositPayment`) + دکمهٔ پرداخت در `MiniHome`/`MiniBookings`.
روت جدیدی اضافه نشده است.

### ۳.۲) پروندهٔ مشتری: یادداشت، عکس و ویس

در شیت «پروندهٔ مشتری» (تب مدیریت ← مشتریان) علاوه بر یادداشت، حالا **درج عکس**،
**بارگذاری ویس از فایل** و **ضبط ویس با میکروفون** هم وجود دارد. سقف‌ها را
سوپرادمین تعیین می‌کند و هر دو طرف (مینی‌اپ و داشبورد وب) از همان عدد خوانده
می‌شوند — عدد ثابتی در کد نمی‌ماند.

کلیدهای `crm.*` در بخش **«پروندهٔ مشتریان (CRM)»**ِ `پنل ادمین ← تنظیمات سیستم`:

| کلید | پیش‌فرض | محدوده | اثر |
|------|---------|--------|-----|
| `crm.note_limit` | 5 | 1–200 | حداکثر یادداشت برای هر مشتری |
| `crm.media_limit` | 10 | 1–500 | حداکثر فایل (عکس + ویس) برای هر مشتری |
| `crm.photo_max_mb` | 5 | 1–50 | سقف حجم هر عکس (مگابایت) |
| `crm.voice_max_mb` | 10 | 1–50 | سقف حجم هر ویس (مگابایت) |
| `crm.media_enabled` | true | — | خاموش = فقط یادداشت متنی؛ بارگذاری عکس/ویس ۴۰۳ می‌شود |

منبع یکتای این اعداد `backend/src/lib/crm-limits.ts` است (`crmLimits()` با `getSetting`
که خودش ۸ ثانیه کش دارد؛ پس «ذخیره» در پنل بدون ری‌استارت سرور اعمال می‌شود).
مقدار نامعتبر یا خارج از محدوده به پیش‌فرض برمی‌گردد تا یک غلط تایپی کل پنل را قفل نکند.
پیش‌فرض‌ها در کاتالوگ با فیلد `defaultValue` اعلام شده‌اند، بنابراین تا وقتی رکوردی در
جدول `Setting` ساخته نشده، همان عدد پیش‌فرض در پنل و در API دیده می‌شود
(برچسب «پیش‌فرض» کنار فیلد).

مسیرهای API (همه از قبل ثبت‌شده بودند؛ روت تازه‌ای اضافه نشد):

| مسیر | متد | تغییر |
|------|-----|-------|
| `/api/dashboard/salons/:id/customers/:customerId` | GET | علاوه بر `customer.notes`/`customer.media`، حالا `notes`/`media` در ریشه و `noteLimit`/`mediaLimit`/`photoMaxMb`/`voiceMaxMb`/`mediaEnabled` را هم برمی‌گرداند |
| `/api/dashboard/salons/:id/customers/:customerId/notes` | GET | `{ notes, limit }` |
| … /notes | POST | اگر تعداد ≥ `note_limit` باشد ۴۰۰ با «حداکثر N یادداشت برای هر مشتری مجاز است…» |
| … /notes/:noteId | DELETE | حذف یادداشت |
| `/api/dashboard/salons/:id/customers/:customerId/media` | GET | `{ media, limit, limits: { mediaLimit, mediaEnabled } }` |
| … /media | POST (multipart: `file`, `type`) | `media_enabled=false` ← ۴۰۳؛ حجم بیش از سقف ← ۴۰۰؛ تعداد ≥ `media_limit` ← ۴۰۰ |
| … /media?mediaId= | DELETE | حذف فایل از دیسک و دیتابیس |

سمت مینی‌اپ `CustomerSheet` (`frontend/src/mini/components/manage.tsx`) از
`getUserMedia({audio:true})` + `MediaRecorder` استفاده می‌کند (خروجی `audio/webm`،
روی iOS `audio/mp4`)، تا ۱۲۰ ثانیهٔ ضبط را شمارش معکوس می‌کند و فایل را با `FormData`
به همان `/media` می‌فرستد؛ به همین دلیل `mapi()` در `mini/lib/store.tsx` وقتی بدنه
`FormData` است هدر `content-type` را نمی‌فرستد. استایل بلوک‌های جدید فقط در
`mini.css` (`mini-cust-*`, `mini-rec-*`) است. داشبورد وب هم (`SalonManager.tsx`،
`DashboardCustomers.tsx`) همین سقف‌ها را از پاسخ پرونده می‌خواند و وقتی
`mediaEnabled` خاموش باشد به‌جای دکمهٔ بارگذاری، پیام «عکس و ویس غیرفعال است» نشان
می‌دهد. فایل‌ها در `uploads/customers/` ذخیره و فقط به همان سالن نشان داده می‌شوند.

### ۳.۳) رزرو با هوش مصنوعی و دستی (`/mini/voice-booking`)

صفحهٔ `frontend/src/mini/pages/MiniVoiceBooking.tsx` است؛ روت تازه‌ای لازم ندارد و
دقیقاً همان سه endpoint سایت را که «رزرو صوتی» پنل (`/dashboard/voice-booking`)
استفاده می‌کند صدا می‌زند — پس `gen-controllers.mjs` اجرا نمی‌شود:

| endpoint | نقش در این صفحه |
|----------|------------------|
| `POST /api/voice/transcribe` | چندپارتی (multipart) با `audio` **یا** `text` + `salonId` + `phone` + `voiceCallId` + `partial` و برای پرسش تکمیلی `field` (یکی از `name/phone/service/date/time`). خروجی: `{voiceCallId, transcript, provider, extracted:{name, phone, service, date, time}}` که `date` میلادی `YYYY-MM-DD` و `time` بیست‌وچهارساعتهٔ `HH:MM` است. `extracted` با `partial` ادغام می‌شود، پس گفتار بعدی فقط همان یک مورد را می‌خواهد |
| `GET /api/salons/<slug>/availability?date=&serviceIds=&employeeId=` | وقت‌های خالی همان روز/خدمت. `serviceIds` اجباری است (بدون آن ۴۰۰ برمی‌گردد) — به همین دلیل ساعت تا خدمت انتخاب نشده نمایش داده نمی‌شود |
| `POST /api/appointments` | ثبت نهایی با `channel:"VOICE"` و `voiceCallId` در حالت صوتی و `channel:"MANUAL"` در حالت دستی؛ برای مهمان (بدون ورود) هم باز است |

قاعده‌های رفتاری که در صفحه پیاده شده:

- **ساعت گفته‌شده با وقت‌های واقعی تطبیق داده می‌شود** (نه محاسبهٔ آفست در کلاینت):
  `HH:MM` استخراج‌شده با ساعت هر بریدۀ آزاد در `timezone` سالن مقایسه می‌شود؛ اگر
  دقیقاً همان ساعت خالی باشد خودکار ثبت می‌شود، اگر پر باشد نزدیک‌ترین وقت ثبت و
  دلیلش در کارت موفقیت نوشته می‌شود (`ساعت … آزاد نبود؛ نزدیک‌ترین وقت … ثبت شد`)،
  و اگر آن روز هیچ وقتی نباشد کاربر به «تکمیل نوبت» می‌رود تا روز دیگر را بزند.
- **هر چه از گفتار فهمیده شده حتی در حالت ناقص در فرم می‌نشیند** (خدمت و روز
  پیش‌انتخاب و ساعت‌های همان روز بارگذاری می‌شود) و فقط موردِ نفهمیده پرسیده می‌شود؛
  چیپ‌های «فقط نام را بگویید» همان `field` سرور را می‌فرستند.
- نام و شمارهٔ استخراج‌شده **مستقیم به بدنهٔ `POST` پاس می‌شود**، نه از `state`
  (در همان دور رندر، `setName` هنوز اعمال نشده و مقدار قبلی فرم جای مشتری ذخیره می‌شد).
- نام/شماره فقط برای نقش `CUSTOMER` از حساب و `profile` محلی پیش‌پر می‌شود؛ سالن‌دار
  می‌تواند برای مشتریِ دیگری رزرو کند.
- **سقف‌ها همان تنظیمات موجود است**: `voice.max_upload_bytes` (پیش‌فرض ۳ مگابایت)،
  `voice.rate_per_hour` (۴۰ برش)، و دروازۀ پلن `withinLimit(salonId, "voiceBooking")`
  که با پیام «رزرو صوتی در پلن فعلی این سالن فعال نیست» رد می‌کند. سقف ضبط کلاینت
  ۶۰ ثانیه است (≈۱/۲ مگابایت `webm`). اگر سوپرادمین `miniapps.features.booking` را
  خاموش کند، تب در نوار پایین اصلاً ساخته نمی‌شود.
- **میکروفون** با `getUserMedia({audio:true})` + `MediaRecorder` است (خروجی
  `audio/webm` و در صورت نبودش `audio/mp4`). چون وب‌ویوهای پیام‌رسان ممکن است روی
  `http` باشد (و مرورگر آن‌جا میکروفون را قفل می‌کند)، دو راه‌جاگزین همان‌جا هست:
  «فایل صوتی» (`<input type=file accept="audio/*">`) و «نوشتن جمله» — هر سه از یک
  endpoint عبور می‌کنند. `localhost` در مرورگر secure context محسوب می‌شود، پس آن‌جا
  میکروفون باز است.
- استایل جدید فقط در `mini.css` با پیشوند `mini-vb-*` (به‌علاوهٔ `hidden-file` و
  `mini-note.is-warn`) است. نوار پایین حالا ۵ تب دارد؛ برچسب تب کوتاه «رزرو هوشمند»
  است (نام کامل در `title`/`aria-label` و عنوان صفحه) تا در عرض ۷۸ پیکسلِ هر تب
  بدون بریدگی جا شود؛ `.mini-tab` هم `min-width:0` گرفت تا یک برچسب بلند هرگز
  نوار را از ۴۲۰ پیکسل بیرون نزند.
- **نوار آرایشگر و روز هرگز قلم نصفه‌پشت‌لبه ندارد**: `.mini-days` و `.mini-avatars`
  در ظرف‌های خودِ این صفحه (`.mini-vb-needs` و `.mini-vb-manual`) با سلکتور مخصوص
  خط‌به‌خط می‌شکنند (`flex-wrap: wrap`، `overflow: visible` و قلم‌ها `1 1 62px/84px`
  با `min/max-width`) — پس حتی اگر قاعدهٔ پایهٔ این کلاس‌ها در سایر صفحه‌ها
  `overflow-x:auto` بماند، در این صفحه چیزی بریده نمی‌شود. نام و عنوان آرایشگر هم `white-space:normal`
  گرفت تا در کارت ۸۴–۱۲۴ پیکسلی با «…» حذف نشود.

### ۳.۴) اسکن کیو‌آر با دوربین، داخل خود وب‌اپ (`components/qr-scanner.tsx`)

«افزودن سالن با لینک» خودکار شده است: در `/mini/favorites` (و در صفحهٔ خانه وقتی هنوز
سالنی ثبت نشده) دکمهٔ **«باز کردن دوربین و اسکن کیو‌آر»** هست. با زدنش یک شیت تمام‌صفحه
باز می‌شود که جریان دوربین را با `navigator.mediaDevices.getUserMedia({ video: { facingMode: "environment" } })`
می‌گیرد و فریم‌ها را محلاً با پردازش تصویر می‌خواند — هیچ درخواست شبکه‌ای برای خواندن
کیو‌آر زده نمی‌شود و تصویر جایی ارسال نمی‌گردد:

- `jsqr` (وابستگی تازهٔ `frontend/package.json`) هر فریم را decode می‌کند. فریم روی یک
  `canvas` پنهان کشیده می‌شود و `getImageData` به آن داده می‌شود؛ طول ضلع به ۶۴۰ پیکسل
  محدود می‌شود تا روی گوشی‌های ضعیف هم روان بماند.
- اگر مرورگر `BarcodeDetector` بومی داشته باشد (کروم اندروید)، بعد از دوازده فریم
  بی‌نتیجه از آن هم در میان حلقه استفاده می‌شود (روی iOS Safari و دسکتاپ وجود ندارد؛
  مسیر `jsqr` همه‌جا کار می‌کند).
- حلقهٔ خواندن با `setTimeout` خود-برنامه‌ریز (هر ۷۰ میلی‌ثانیه) کار می‌کند، نه
  `requestAnimationFrame` — چون در تب پس‌زمینه rAF خاموش می‌شود و اسکن گیر می‌کرد.
  در حالت توسعه هم StrictMode دوبار effect را اجرا می‌کند، پس باز/بسته بودن اسکن در
  پرچم جداگانه‌ای نگه داشته می‌شود تا remount آن را نبندد.
- وقتی کد خوانده شد: ویبرهٔ کوتاه، سبز شدن کادر، بسته شدن شیت و آزاد کردن دوربین
  (`track.stop()`). خروجی که لینک باشد (`https://…/s/mah`) با `slugFromAnything` (اکنون در
  `lib/favorites.ts`) به اسلگ تبدیل می‌شود، در کادر لینک می‌نشیند و افزودن خودکار اجرا می‌شود؛
  در صفحهٔ خانه، سالن به علاقه‌مندی‌ها اضافه شده و کاربر به `/mini/s/<slug>` می‌رود. اگر کاربر
  وارد نباشد همان اسلگ در `nobino.mini.favorites.pending` یادداشت می‌شود و بعد از ورود اضافه می‌گردد
  (همان مسیر قدیمیِ باز کردن لینک از بیرون).
- دکمه فقط وقتی نشان داده می‌شود که `cameraScanSupported()` درست باشد
  (مرورگر `getUserMedia` دارد و صفحه روی https یا localhost است). اگر دوربین باز نشد،
  متن خطای فارسی مربوطه (ردِ دسترسی / نبودِ دوربین / دوربین اشغال / نشانی ناامن) در همان
  شیت نوشته می‌شود و کادر چسباندن لینک سر جایش می‌ماند، پس هیچ مسیری بسته نمی‌شود.
- کیو‌آرِ قابل استفاده همان چیزی است که پنل می‌سازد (`components/SalonQrCard.tsx`): لینک
  عمومی سالن. مقادیر دیگر (متن ساده، واتساپ، اینستاگرام) به اسلگ تبدیل نمی‌شوند و فقط
  توست خطا می‌دهد.

### ۳.۵) مینی‌اپ روی نشانی خودِ سالن (`lib/host.ts`)

نشانی هر سالن دو صفحه می‌دهد: صفحهٔ وبِ سالن (چیزِ همیشگی) و مینی‌اپ آن سالن.
یعنی `mah.nobino.ir/mini` در پروداکشن و `mah.localhost:5175/mini` (یا `:3100`) در توسعه
باز می‌شود و:

- صفحهٔ **خانهٔ مینی‌اپ همان سالن است** — مثل حالتی که کاربر لینک `/mini?salon=mah` را
  باز کرده باشد (`source: "link"`)، با برچسب «از لینک/نشانی سالن».
- هر بار که این صفحه باز شود، همان سالن در **علاقه‌مندی‌ها** ثبت می‌شود: کاربر وارد‌شده
  `POST /api/favorites/<id>` می‌گیرد (اگر قبلاً حذفش کرده باشد، دوباره برمی‌گردد) و مهمان
  اسلگ را در `nobino.mini.favorites.pending` نگه می‌دارد تا بعد از ورود اضافه شود.
  افزودن idempotent است: باز کردن پشت‌سرهم فهرست را تکراری یا پر نمی‌کند.
- سالنِ **خودِ کاربر** استثنا است: اگر بیننده مالک همان سالن باشد (`salon.isOwnerViewer`)
  در علاقه‌مندی‌ها ثبت نمی‌شود، چون خانه‌اش همین «سالن شما» است و ردیف علاقه‌مندیِ سالن
  خودش فقط فهرست را شلوغ می‌کرد.

چطور کار می‌کند:

- `App.tsx` روی ساب‌دامین سالن، صفحهٔ عمومی را رندر می‌کند — استثنای `/mini` و `/mini/*`
  که مینی‌اپ را نشان می‌دهند. رندر باید داخل یک `<Route path="/mini/*">` باشد، چون
  جدول مسیرهای `MiniApp.tsx` نسبت به همین پیشوند تعریف شده و بیرون از آن خالی می‌ماند.
- `mini/lib/host.ts` ماژول تازه است و عمداً مستقل نوشته شده (هیچ import از `@/lib/*` ندارد):
  `miniHostSlug()` میزبان را از دامنهٔ ریشه (`VITE_ROOT_DOMAIN`، در نبودش دو برچسب آخر،
  و در لوکال `localhost`) جدا می‌کند. برچسب‌های خدماتی (`www`، `api`، `panel`، `admin`،
  `mini`، `cdn`، `static`، `uploads` …) و میزبان‌های IP‌مانند سالن حساب نمی‌شوند.
- در `resolveHomeSalon` این اسلگ بلافاصله بعد از پارامترهای کوئری می‌آید، پس لینک
  ارسالی پیام‌رسان (`?salon=…`) همیشه بر نشانی میزبان اولویت دارد.

نکتهٔ مهم: `localStorage` هر ساب‌دامین جدا است. کاربری که روی `nobino.ir/mini` وارد شده
در `mah.nobino.ir/mini` مهمان به نظر می‌آید و یک‌بار باید OTP بزند؛ تا آن لحظه سالن در
فهرست pendingِ همان نشانی می‌ماند و با اولین ورود اضافه می‌شود. نشانی‌های `/s/<slug>` و
ساب‌دامین بدون `/mini` مثل قبل فقط صفحهٔ عمومی سالن‌اند.

قطب «مینی‌اپ» روی صفحهٔ سالن، ریشهٔ نشانی همان سالن + `mini` است — `mah.localhost:5175/mini`
در توسعه (پورت حفظ می‌شود) و `mah.nobino.ir/mini` در پروداکشن؛ کادر «لینک افزودن به
علاقه‌مندی‌ها»، دکمهٔ کپی و PNG/SVG همه از همان رشته ساخته می‌شوند و اگر صفحه را روی خودِ

`<پایهٔ مینی‌اپِ پنل>?salon=<slug>` برمی‌گردد و اگر آن پایه هم تنظیم نشده باشد همان صفحهٔ وب
اسکن می‌شود — کیو‌آر هیچ‌وقت خالی نمی‌ماند.

## ۴) امنیت ورود

- امضای `initData` سمت سرور با `HMAC-SHA256` و کلید `WebAppData` چک می‌شود
  (`backend/src/lib/mini/webapp-data.ts`)؛ `auth_date` کهنه رد می‌شود.

- پیوند پیام‌رسان ↔ کاربر در همان جدول `Setting` با کلید

  است، فایلِ کار ناتمامِ نشست دیگری)؛ `vite build` + `prerender.mjs` بدون خطا (۲۵۱ صفحه).

**دور «مینی‌اپ روی نشانی سالن»** — هم `mah.localhost:5175/mini` (Vite dev) و هم
`mah.localhost:3100/mini` (باندل `dist`) در مرورگر باز و با `GET /api/favorites` راستی‌آزمایی شد:

- مهمان روی `mah…/mini`: خانه = «سالن زیبایی ماه» با برچسب «دربارهٔ سالن · از لینک/نشانی سالن»
  و `nobino.mini.favorites.pending = ["mah"]`. روی `sepideh…/mini` هم همان رفتار با
  «سالن سپیده» دیدنی بود (تشخیص از میزبان است، نه اسلگ ثابت).
- مشتریِ وارد‌شده (`09123456789`): علاقه‌مندی‌ها یک‌بار با API خالی شد، سپس یک باز کردن
  صفحه → `total=1` با ردیف تازه (`cmvztyq5n0008v970cghhjvqm:mah`). باز کردن دوم: همان
  یک ردیف، بدون تکرار. باز هم خالی نبود اگر کاربر حذفش کند — هر بار دوباره می‌آید.
- مالک همان سالن (`09120000001`، نگار رضایی): خانه = سالن خودش با چیپ «سالن شما» و
  دکمه‌های «نوبت دستی / نوبت هوشمند»، و `favorites` بعد از چند باز کردن **خالی ماند**
  (گارد `isOwnerViewer`). همان حساب روی `sepideh…/mini` (سالن دیگر) → `total=1: sepideh`.
  ردیف‌های آزمایشی پاک شدند و توکن‌ها از `localStorage` نشانی‌های تست حذف شد.
- نشانی‌های نگاشته‌شده: `noor.localhost:5175/mini` → «سالن یافت نشد» (بدون فاش شدن سالن
  دیگر، بدون pending) و `localhost:5175/mini` مثل قبل صفحهٔ راهنمای اسکن.
- ناوبری SPA روی ساب‌دامن سالم است: دکمهٔ رزرو → `/mini/s/mah`، تب‌ها و `/mini/favorites`
  («علاقه‌مندی‌های من · ۱ سالن» + دکمهٔ دوربین).
- در همین دور یک نکتهٔ موجود کشف شد (تغییر داده‌نشده): اگر `/api/auth/me` چند بار ۵۰۰
  برگرداند (لحظهٔ سنگین bوست/پراکسی)، مینی‌اپ کاربر را «خارج» می‌شمارد و
  `writeToken("")` توکن ذخیره‌شده را پاک می‌کند (`lib/store.tsx:283`).

**دور «آدرس کیو‌آر مینی‌اپ = نشانی خودِ سالن»** — تابع `salonMiniUrl` با یک باندل موقت
`esbuild` از همان فایل کامپوننت (`tmp-qr-card-bundle.cjs`، بعد از اجرا حذف شد) روی شش میزبان
تست و بعد در مرورگر راستی‌آزمایی شد:

| میزبان صفحهٔ سالن | آدرس کیو‌آر مینی‌اپ |
|---|---|
| `localhost:5175` (فرم `/s/mah`) | `http://mah.localhost:5175/mini` |
| `mah.localhost:5175` (همان ساب‌دامین) | `http://mah.localhost:5175/mini` (بدون پیشوند تکراری) |
| `nobino.ir` | `https://mah.nobino.ir/mini` |
| `mah.nobino.ir` | `https://mah.nobino.ir/mini` |
| `192.168.1.5:5175` | `<miniUrl پنل>?salon=mah` |
| `nobino.ir` + دامنهٔ اختصاصی VERIFIED | `<miniUrl پنل>?salon=mah` |

- در مرورگر روی `mah.localhost:5175/` و `localhost:5175/s/mah`، بعد از زدن قطب «مینی‌اپ»،
  کادر متن و کادر «لینک افزودن به علاقه‌مندی‌ها» هر دو `http://mah.localhost:5175/mini` را

- باز شدن همین آدرس در دور قبلی تست شده بود: خانه = همان سالن و افزودن خودکار به
  علاقه‌مندی‌ها (`docs/miniapp.md` §۳.۵ و دور تستی بالایی).

**وضعیت build**: بعد از افزودن تشخیص نشانی، `npx tsc -p tsconfig.json --noEmit` بدون خطا بود و

نوشت؛ همان باندل روی `:3100` با ساب‌دامین تست شد. دو تغییر بعدی — گارد «سالن خودِ کاربر ثبت
نمی‌شود» در `MiniHome.tsx` و آدرس تازهٔ کیو‌آر در `SalonQrCard.tsx` — پس از آن build آمدند و

همان `tsconfig.json` کل پروژه یا `npm run verify` است.

## ۶) نکات و محدودیت‌های شناخته‌شده

- `/api/appointments` و `/api/dashboard/stats` برای صاحب سالن **اولین** سالن او را
  ملاک می‌گیرند؛ همین سالن، صفحهٔ خانهٔ مینی‌اپ او هم می‌شود. صاحب چند سالن باید برای
  بقیه به پنل وب برود (رفتار قبلی سایت، تغییر داده‌نشده).
- خانه فقط یک سالن را در سربرگ نشان می‌دهد؛ بقیهٔ سالن‌های کاربر از راه نوار
  علاقه‌مندی‌ها، `/mini/favorites` و «نوبت‌های من» باز می‌شوند. با دو علاقه‌مندی یا بیشتر
  (و بدون سالن خود/نوبت قبلی) خانه خودش فهرست می‌شود — این همان چیزی است که خواسته شده:
  هیچ سالن نمونه‌ای از سوی سوپرادمین فاش نمی‌شود.
- سقف علاقه‌مندی در مینی‌اپ ۲۰ سالن است (`MAX_FAVORITES`)؛ اضافه کردن بیست‌ویکم پیام
  «بیش از ۲۰ سالن نمی‌شود داشت» می‌دهد. خودِ جدول `Favorite` سقفی ندارد و پنل وب هم
  همان endpoint را مصرف می‌کند.
- اسکن وقتی کاربر وارد نشده، فقط اسلاگ را در `localStorage` همان دستگاه می‌نویسد
  (حداکثر ۶ اسلاگ آخر) و بعد از ورود روی همان دستگاه اضافه می‌شود؛ اگر دستگاه را عوض
  کند، آن اسکن‌ها از دست می‌روند (جایگزینش سرور-side «pending» است که جدول نمی‌خواهد).
- افزودن از صفحهٔ «علاقه‌مندی‌های من» با لینک/اسلگ، اسلاگ را از سه شکل بیرون می‌کشد:
  خودِ اسلاگ، `https://<slug>.domain/` و `https://domain/s/<slug>`؛ دامنهٔ اختصاصی
  تأییدشدهٔ سالن را نمی‌توان از روی آدرس به اسلاگ برگرداند، پس آن حالت رد می‌شود.
- ویرایش «نام/شمارهٔ جایگزین» در `/mini/me` فعلاً فقط در `localStorage` همان دستگاه
  می‌ماند، چون endpoint ویرایش پروفایل در این پروژه وجود ندارد.
- **نشانی سالن و نشست جدا**: `localStorage` (توکن مینی‌اپ، pending و سبد رزرو) به میزبان
  وابسته است، پس `mah.nobino.ir/mini` نشستِ `nobino.ir/mini` را نمی‌بیند و کاربر یک‌بار
  باید OTP بزند. اشتراک توکن بین ساب‌دامین‌ها (کوکی `Domain=.nobino.ir`) عمداً انجام نشده:
  روی `localhost` کوکی دامنه‌ای کار نمی‌کند و نشست مینی‌اپ هم الآن هدر نمی‌رود.
- **دامنهٔ اختصاصی سالن** (`salon.customDomain`) در تشخیص §۳.۵ جایی ندارد: میزبان
  `beautyhouse.com` هیچ اسلگی در خودش ندارد، پس `/mini` روی آن مثل دامنهٔ اصلی رفتار
  می‌کند. همان محدودیتی که صفحهٔ عمومی سایت هم دارد (`lib/subdomain.ts` فقط ساب‌دامین را
  می‌شناسد)؛ پشتیبانی‌اش نیاز به نگاشت دامنه←اسلگ سمت سرور دارد.
- کارت کیو‌آرِ «مینی‌اپ» از نشانی خودِ سالن + `/mini` استفاده می‌کند (§۳.۵)؛ پارامتر
  `?salon=<slug>` فقط حالت پشتیبانِ میزبان‌های IP و دامنهٔ اختصاصی است. چون هر دو شکل
  کار می‌کند، کیو‌آرهای چاپ‌شدهٔ قدیمی هم معتبرند و لازم به بازچاپ نیستند.
- صفحه‌بندی «بارگذاری بیشتر» فقط در `/mini/appointments` مانده است (فهرست نوبت‌ها)؛
  خانه دیگر فهرستی برای صفحه‌بندی ندارد.
- رنگ `accent` فقط `hex` سه‌ یا شش‌رقمی پذیرفته می‌شود؛ ورودی نامعتبر به رنگ پیش‌فرض برمی‌گردد.
- **دادهٔ نمونه با شمارهٔ ۱۲ رقمی**: در بذر فعلی هیچ‌کدام از ۴۰ مشتری نمونه (`09124000001xx`)
  با الگوی OTP (`^0?9\d{9}$`، ۱۱ رقم) جور نیست، پس با آن شماره‌ها نمی‌شود وارد شد.
  برای دیدن سمت مشتری یا شمارهٔ معتبر بسازید یا از مسیر پیام‌رسان (`/api/mini/session`) وارد شوید.
  (این محدودیت دیتاست توسعه است، نه مینی‌اپ؛ تست‌های بالا با مشتری تازه‌ثبت‌نام‌شده انجام شد.)
- نوبت حضوری پیامک تأیید نمی‌فرستد (همان رفتار پنل وب) و فقط در تقویم سالن ثبت می‌شود؛
  برای مشتری آنلاین پیامک «تأیید ساعت» سالن ملاک است.
- مبالغ در تب «مالی» فشرده نمایش داده می‌شوند («۲/۹ میلیون»)؛ عدد دقیق در پنل وب هست.

## ۷) پس از گرفتن این نسخه

```bash
node backend/scripts/gen-controllers.mjs   # ثبت /api/mini/* در controller ها
cd backend && npm run build && npm start
cd frontend && npx vite build
```

`manifest.json` این ماژول پنج مسیر `mini/*` را (به‌جز `mini/config` که از قبل بود)
افزوده و کنترلرهای تولیدشده هم به همان ترتیب بازتولید شده‌اند.

نسخهٔ «خانهٔ سالن‌محور» هیچ مسیر جدیدی اضافه یا حذف نکرد (فقط بدنهٔ چند handler موجود
غنی‌تر شد)، پس برای به‌روزرسانی لازم نیست `gen-controllers.mjs` را دوباره اجرا کنید؛
`npm run build` در `backend/` و `npx vite build` در `frontend/` کافی است. کلید
`miniapps.default_salon` از کاتالوگ تنظیمات حذف شده است؛ اگر جایی ذخیره شده باشد
ردیفش در جدول `Setting` می‌ماند ولی دیگر هیچ‌جا خوانده نمی‌شود (پاک کردنش اختیاری است:
`DELETE FROM "Setting" WHERE key = 'miniapps.default_salon'`).

دور «سادگی بیشتر» (اطلاعیه‌ها، پشتیبانی، کیف پول، کارهای نوبت، نوبت حضوری، هاب چهارتبله)
**هم فقط فرانت‌اند است** و هیچ مسیر تازه‌ای نساخته؛ همان دو دستور بالا کافی است و
`gen-controllers.mjs` را اجرا نکنید. تنها چیزی که از سمت سرور لازم است روشن بودن
`/api/notifications`، `/api/support`، `/api/wallet` و `/api/dashboard/salons/:id/*` است —
که همه در همین پروژه وجود دارند.

دور «علاقه‌مندی‌ها» هم همین‌طور است: از سه endpoint آمادهٔ `/api/favorites*` و جدول
`Favorite` موجود استفاده می‌کند، هیچ مسیر تازه‌ای نساخته و `gen-controllers.mjs` لازم ندارد.
تنها تغییر بیرون از ماژول، دو قطب «صفحهٔ وب / مینی‌اپ» در `components/SalonQrCard.tsx` است
(فقط `GET /api/mini/config` را برای `miniUrl` می‌خواند) و حذف `defaultSalon` از
`backend/src/lib/mini/config.ts`، `backend/src/routes/api/mini__config.ts` و
`backend/src/lib/settings-catalog.ts`.
