# تبدیل گفتار فارسی به متن با مدل محلی Shenava

Nobino از سه مسیر برای تبدیل گفتار استفاده می‌کند و مسیر اول می‌تواند **کاملاً محلی و آفلاین** باشد:

```
local (Shenava/sherpa-onnx) → groq → huggingface → cloudflare → deepgram → openai → mock
```

ترتیب در تنظیمات `stt.order` (پنل سوپرادمین → هوش مصنوعی) قابل تغییر است و هر رباتی که
در دسترس نباشد (کلید/مدل نداشته باشد یا خطا بدهد) خودکار رد می‌شود.

---

## چرا sherpa-onnx؟

مدل اصلی `Shenava-Koochik-v1.0` یک چک‌پوینت **NeMo** است که فقط با پایتون اجرا می‌شود و
به سرویس جانبی + PyTorch (حدود ۲ گیگ RAM) نیاز دارد. همان مدل به‌صورت ONNX برای
sherpa-onnx منتشر شده و پکیج `sherpa-onnx-node` باینری پیش‌ساختهٔ Node دارد؛ پس مدل
**داخل همین پروسهٔ بک‌اند NestJS** اجرا می‌شود:

- بدون پایتون، بدون کانتینر اضافه، بدون پورت جدید
- بدون API key و بدون هزینهٔ سرویس ابری
- سازگار با ویندوز (توسعه) و لینوکس (داکر)

| ویژگی | مقدار |
|---|---|
| پارامترها | ۱۱۴M (FastConformer CTC) |
| حجم مدل | ~۴۵۹ MB |
| ورودی | ۱۶ kHz مونو (ffmpeg خودش تبدیل می‌کند) |
| حالت | offline (نه streaming) |
| RAM | ~۰.۶–۱ GB (اندازه‌گیری‌شده: ~۵۳۶ MB با مدل بارگذاری‌شده) |
| CPU | ۱–۲ vCPU (`stt.local.num_threads`) |
| GPU | لازم نیست |
| مجوز | Apache-2.0 |

سرعت اندازه‌گیری‌شده روی یک ماشین توسعه: **RTF ≈ ۰.۰۵** یعنی هر ۱۰ ثانیه صدا
حدود ۰.۵ ثانیه پردازش می‌شود (به‌مراتب سریع‌تر از سرویس‌های ابری و کاملاً آفلاین).

کیفیت منتشرشدهٔ خانوادهٔ مدل: WER ۷.۴۹٪ روی golden-6669 و ۱۰.۶۴٪ روی FLEURS-fa.

## نصب خودکار (پیش‌فرض)

**هیچ کاربری چیزی نصب نمی‌کند و ادمین هم لازم نیست دستی کاری کند.** مدل و ffmpeg
یک‌بار روی **سرور** (نه روی دستگاه مشتری‌ها) آماده می‌شوند و مشتری فقط با مرورگر
مثل قبل دکمهٔ میکروفون را می‌زند.

| محیط | چه اتفاقی می‌افتد |
|---|---|
| **داکر** (`docker compose up -d`) | `ffmpeg` در ایمیج نصب است؛ مدل در اولین بوت در پس‌زمینه دانلود و در volume ماندگار `asr_models` ذخیره می‌شود |
| **سرور بدون داکر** (`npm start`) | `paas-start` یک پروسهٔ پس‌زمینه اجرا می‌کند که مدل (و در صورت نبود، ffmpeg) را در `models/` می‌آورد |
| **توسعه** (`npm run dev`) | همان کار در پس‌زمینه؛ لاگ در `.dev-logs/asr.log` |

نکته‌های مهم:

- دانلود **بوت را کند نمی‌کند**؛ سرور فوراً بالا می‌آید. تا وقتی مدل آماده نشده،
  زنجیرهٔ STT از Groq/HuggingFace/… استفاده می‌کند و مشتری هیچ خطایی نمی‌بیند.
- دانلود قابل‌ادامه است (Range + تلاش مجدد)؛ قطعی شبکه فقط یعنی اجرای بعدی
  از همان بایت ادامه می‌دهد.
- با `AUTO_ASR=0` خاموش می‌شود (یا `AUTO_ASR_MODEL=0` / `AUTO_ASR_FFMPEG=0` جداگانه).
- برای سرور بدون اینترنت، مدل را جای دیگری دانلود و با `SHENAVA_MODEL_DIR` به آن اشاره کنید.

### وابستگی Node

`sherpa-onnx-node` یک وابستگی عادی npm است و با `npm install`/`npm ci` خودکار نصب
می‌شود (باینری آمادهٔ ویندوز/لینوکس/مک دارد، بدون build).

## راه‌اندازی دستی (اختیاری / عیب‌یابی)

```bash
npm run asr:setup                                   # همان کاری که بوت خودکار می‌کند
npm run asr:model                                   # فقط مدل، با لاگ کامل و resume
npm run asr:model -- --force                        # دانلود دوباره
npm run asr:check                                   # بررسی مدل + sherpa-onnx + ffmpeg
npm run asr:check -- --wav test-16k-mono.wav        # تست واقعی (RTF و RAM را چاپ می‌کند)
```

محل فایل‌ها: `models/shenava-koochik-v1.0-sherpa-onnx/` برای مدل و
`models/.bin/ffmpeg(.exe)` برای باینری خودکار. هیچ‌کدام در git نیستند.

### تنظیمات

| کلید | مقدار پیش‌فرض | توضیح |
|---|---|---|
| `stt.order` | `local,groq,huggingface,cloudflare,deepgram,openai` | ربات اول = محلی |
| `stt.local.enabled` | `true` | خاموش کردن موتور محلی |
| `stt.local.model_dir` | خالی | خالی = `models/shenava-koochik-v1.0-sherpa-onnx` |
| `stt.local.num_threads` | `2` | تعداد ترد CPU |
| `stt.local.ffmpeg` | خالی | خالی = `models/.bin` یا `ffmpeg` در PATH |
| `AUTO_ASR` | `1` | دانلود خودکار مدل/ffmpeg در بوت |

در `.env` هم `SHENAVA_MODEL_DIR`، `FFMPEG_PATH` و `AUTO_ASR` قابل تنظیم‌اند (کلیدهای پنل اولویت دارند).

### بررسی وضعیت

- پنل سوپرادمین → «هوش مصنوعی» → کارت «Shenava محلی» (وضعیت configured)
- یا `GET /api/admin/ai/status` و بخش `sttProviders`
- تست عملی: `POST /api/voice/transcribe` با یک فایل صوتی

اگر مدل پیدا نشود، دلیلش در پاسخ status (فیلد `reason`) و در `errors` مسیر transcribe
برمی‌گردد و زنجیره به Groq و بقیه می‌رود؛ ثبت نوبت شکست نمی‌خورد.

## داکر

مدل داخل ایمیج نمی‌رود (۴۵۹MB)؛ در volume ماندگار نگه‌داری می‌شود:

```yaml
volumes:
  - asr_models:/app/models
```

با اولین `docker compose up -d --build` همه‌چیز خودکار است. مدل در
`/app/models/shenava-koochik-v1.0-sherpa-onnx` ذخیره می‌شود و بعد از restart/آپدیت
باقی می‌ماند. `ffmpeg` هم در ایمیج نصب است.

اگر می‌خواهید مدل را از قبل روی میزبان داشته باشید، به‌جای volume نام‌دار از bind mount
استفاده کنید و مالکیت پوشه را به uid=1001 بدهید:

```yaml
volumes:
  - ./models:/app/models
```

```bash
sudo chown -R 1001:1001 ./models   # لینوکس
```

## نکات فنی

- **مدل offline است**؛ برای هر کلیپ جدید یک stream تازه ساخته می‌شود. برای همین
  flow «ضبط کوتاه → متن → استخراج نوبت» مناسب است، نه تشخیص زندهٔ هم‌زمان.
- **عددها به شکل گفتاری** برمی‌گردند (مثلاً «ساعت ده»). استخراج نوبت با LLM همین را
  می‌فهمد؛ اگر جایی رقم خواستید، `persian_itn.py` همان مخزن را پورت کنید.
- **نرمال‌سازی per-feature را دستی فعال نکنید.** متادیتای این اکسپورت عمداً
  `normalize_type` را خالی گذاشته و sherpa-onnx همین رفتار درست را اعمال می‌کند.
- **حافظه:** مدل یک‌بار در هر پروسه لود و کش می‌شود (اندازه‌گیری‌شده ~۵۳۶MB)؛ با
  `pm2 -i max` یا چند worker، هر worker همین مقدار را جدا می‌گیرد. برای یک سرور
  کوچک یک worker کافی است.
- **هم‌زمانی:** decodeها روی یک recognizer صف می‌شوند (مدل thread-safe نیست برای
  decode موازی). برای ترافیک بالا چند پروسه یا صف خارجی لازم است.

## عیب‌یابی

| نشانه | علت | راه‌حل |
|---|---|---|
| `مدل محلی پیدا نشد` | دانلود نشده یا مسیر غلط | `npm run asr:model` یا `SHENAVA_MODEL_DIR` |
| `ffmpeg پیدا نشد` | دانلود خودکار خاموش/شبکه قطع | `npm run asr:setup` |
| متن خالی | صدای بی‌کیفیت/سکوت | دوباره تست با WAV واضح |
| کندی زیاد | ترد کم / CPU اشغال | `stt.local.num_threads=4` |
| خروجی نامفهوم | نرمال‌سازی دستی فعال شده | overrideها را بردارید |
